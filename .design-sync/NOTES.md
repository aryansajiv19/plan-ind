# design-sync notes

## This repo is the "cards" shape, not a component library

`/design-sync` is built for a design-system **repo** — it compiles the real
components into `_ds_bundle.js` with `.d.ts` contracts and `.prompt.md` docs so
Claude Design's agent can build new screens out of them.

plan-ind is not shaped like that, and the sync deliberately does not pretend
otherwise. `design-system/dist/` is a handful of self-contained HTML preview
cards carrying `<!-- @dsCard group="..." -->` markers, generated by
`design-system/build.mjs`. `PhotoWall` / `TiltCard` / `VoteState` are app
components wired to Supabase types and Next — they are not a publishable
library, and extracting one is a separate, much larger piece of work
(offered to the owner 2026-09-02, deferred).

So: **run `node design-system/build.mjs`, then upload `design-system/dist/**`
as plain files.** Do not run the converter (`package-build.mjs`) against this
repo — there is no `dist/` of compiled components for it to consume.

## Tokens are parsed, never copied

`design-system/tokens.mjs` reads the live values out of `app/globals.css` at
build time. The previous bundle hand-copied them and rotted for weeks. If the
token block structure in `globals.css` changes, `tokens.mjs` throws rather
than silently emitting a stale palette — fix the reader, don't re-copy values.
