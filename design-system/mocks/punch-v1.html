Three warm values, three different jobs

What each one is for

If two of these ever mean the same thing, one of them should be retired. They are separated by form — fill, bare text, bordered panel — not by hue, because a warm palette cannot separate them by hue.

FILL ONLY

Punch

#C34A2D · white ink 4.84

The primary action, and the decided moment. At most one per screen. Never text, never a border.

TEXT ONLY

Accent

Always inside its bordered panel. Never bare text, never a filled button.

A collision I introduced, and it is not the one that was flagged

Accent and error are the same colour

The risk raised was vermilion against the error colour. Measured, that pair is fine — ΔL* 20.2, opposite ink polarity, and different forms. The real collision is #BF977D against #F08A78: 15° of hue, ΔL* 2.6, contrast 1.08. They are effectively one colour, they are both text, and I shipped the second into §23.9c without checking it against the first.

Hue cannot fix this and neither can lightness. All three warm values want the L* 45–70 band, and a cool error would be off-identity. So the separator is form, and it has to be mandatory: error always carries its bordered panel; accent text never has a border. That is already how .auth-error renders today, so this is a rule catching up with the code rather than a change to it. The thing to forbid is "simplifying" an error into bare coloured text — at contrast 1.08 against a kicker, that is indistinguishable from a section label.
